# balance-sim

수치는 감으로 바꾸지 않는다. **바꾸기 전 기준을 저장하고, 바꾼 뒤 같은 시드로 비교한다.**

## 도구
`tools/balance_sim.py` — 실제 게임 코드(Player, Enemy, Boss, 무기, 게이지)를 창 없이 돌린다. 평평한 시험장(44x18칸)에서 봇이 싸운다. 전체(6 시나리오 x 3 무기 x 2 봇 x 10 시드)가 몇 초면 끝난다.

- 시나리오: `slum`, `thrower`, `hound`, `guard` (1:1), `group` (슬럼2·사냥개·투척병), `boss`
- 봇: `stand` (피하지 않고 맞붙음 = 서툰 플레이의 하한), `dodge` (예고 끝 0.22초 전에 반대쪽으로 대시 = 예고를 읽는 플레이)
- 건틀릿 봇은 게이지가 충전 하한+8% 아래면 철파이프로 바꿔 채우고, 거기서 20% 더 차면 다시 든다 (무기 2칸의 의도된 쓰임)
- 열: 승률, 사망률, 처치 시간(이긴 판 평균), 잃은 HP, 끝 게이지, 최저·최고 게이지, 오버로드 횟수, 구간별 머문 시간 비율

## 절차
1. 기준 저장: `python tools/balance_sim.py --save tools/balance_base.json` (이미 있고 코드가 그 뒤로 안 바뀌었으면 생략)
2. 수치를 바꾼다 (`src/config.py`).
3. 비교: `python tools/balance_sim.py --compare tools/balance_base.json` — 줄 끝에 `win 1.0->0.8` 같은 차이가 붙는다. 관련 시나리오만 보려면 `--scenario hound guard --weapon pipe`.
4. 시작 게이지가 결과를 크게 바꾼다. 보스·위험 구간 수치는 `--gauge 30`, `--gauge 60`, `--gauge 85`를 모두 본다.
5. 의도한 방향으로 움직였고 다른 시나리오가 무너지지 않았으면, 새 기준을 `--save`로 덮어쓰고 `docs/DECISIONS.md`에 바꾼 수치와 전후 숫자를 적는다.

## 읽는 법·주의
- 봇은 점프하지 않고 강화(E)를 쓰지 않는다. 지형·발판 문제는 이 도구로 알 수 없다 (실제 방은 `playtest-capture`).
- `stand`에서 잃은 HP 0이면 "버튼만 연타해도 이긴다"는 뜻이다. 적이 예고 중 맞으면 끊기는지(경직) 확인할 것.
- 사망은 HP 0 또는 게이지 0이다. 끝 게이지·최저 게이지가 0 근처면 게이지 사망이다.
- 숫자는 사람의 체감을 대신하지 않는다. 결과를 보고한 뒤 사용자 플레이 테스트를 권한다.
- 수치 변경은 기획 결정이다. 시뮬레이션 결과로 근거를 보이고, 큰 변경은 사용자에게 먼저 묻는다.
