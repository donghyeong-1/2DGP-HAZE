# haze-inari: INARI 화풍 연출

> **보류 (2026-11-24).** 이 절차로 만든 시안(붓질 초승달 `inari-smear`, 맞부딪침 반짝임 `glint`)을 사용자가 보고
> "픽셀로 찍어내는 느낌은 비슷하지만 퀄리티 차이가 너무 난다"며 쓰지 않기로 했다. 스킬과 분석 자료는 남겨 두지만,
> 사용자가 이름으로 부르지 않는 한 이펙트는 `haze-fx`로 만든다. 반짝임은 게임에서 뺐고 두 시안 모두 `--look` 전용이다.
> 다시 꺼낼 때는 시안의 품질(모양의 완성도)부터 올려야 한다: 기법 목록을 옮기는 것만으로는 그 수준이 나오지 않았다.

`haze-fx`가 **어떻게 굽는가**(fxkit 사용법)라면, 이 스킬은 **무엇을 어떤 순서와 세기로 넣는가**다.
INARI(스팀 상점 영상)를 프레임 단위로 재서 얻은 기법과, 그것을 우리 엔진(pico2d)에서 구현한 방법, 사용자가 반려한 시도에서
배운 것을 모았다. 그림·이름·캐릭터는 가져오지 않는다. 가져오는 것은 연출의 문법이다.

근거가 된 측정값과 장면별 관찰은 `references/inari-analysis.md`에 있다. 새 영상을 분석할 때는 `scripts/video_probe.js`.

## 1. 화풍의 원칙 (왜 그렇게 보이는가)

1. **진한 색 면이 주인공이고 흰색은 조금만.** 초승달·원반·별은 진하고 채도 높은 한 가지 색으로 꽉 채운다. 흰색은 터지는 첫 한 장,
   가운데 작은 별, 불티, 화면을 가르는 빛줄기에만 쓴다. 흰색이 넓으면 색이 씻겨 힘이 빠진다 (처형 원반 프레임: 화면의 붉은색 약 11%, 흰색 약 2%).
2. **색 면은 아주 짧다.** 베기의 색 면은 2~3프레임(약 0.08초)만 보이고 사라진다. 길게 남기면 무겁고 둔해진다.
   남는 것은 가는 흰 호, 별빛, 바닥의 불꽃 궤적 같은 가벼운 것들이다(0.3~0.6초).
3. **색이 차례로 바뀐다: 회색 예고 → 흰색 → 진한 색 → 가늘어짐.** 한 장씩이다. 회색 한 장이 "온다"를 알리고, 흰 한 장이 "지금"을 찍는다.
4. **모양은 붓질이다.** 끝이 붓끝처럼 갈라지고, 움직임이 시작된 쪽 가장자리는 가로 픽셀 줄로 찢긴다. 완전한 원·같은 길이의 가시·고른
   고리는 기계가 그린 티가 난다. 큰 덩어리(폭발 몸통)는 도형이 아니라 불규칙한 입자 무더기로 만든다(haze-fx 1-2절).
5. **화면이 멈추지 않는다.** 영상 2.88초 동안 완전히 같은 프레임이 한 번도 없다. 무게는 정지가 아니라 **느려짐 + 암전 + 한 장짜리
   강한 그림의 연속**으로 낸다. (사용자도 화면 정지·컷인을 "흐름에 방해된다"고 뺐다.)
6. **큰 순간에는 화면 전체가 반응한다.** 배경이 어두워지고(처형 전 0.3초 동안 어두운 픽셀 45% → 60%), 빛줄기가 화면을 가르고,
   배경까지 렌즈처럼 휘며 빨강·초록·파랑이 갈라진다. 이펙트만 화려하고 배경이 그대로면 스티커를 붙인 것처럼 보인다.
7. **색에 뜻이 있다.** 주인공의 공격 = 게이지 구간 색(위험 90%+는 레드) + 흰색, 적의 공격 = 다른 한 색, 표식·조준 = 금색.
   한 장면에 주인공 쪽 색은 하나만 쓴다.

## 2. 공격 등급별 문법 (무엇을 얼마나)

화려함은 **등급의 차이**에서 나온다. 평타에 큰 연출을 다 넣으면 처형이 묻히고 화면이 피로하다. 새 공격을 만들면 먼저 등급을 정한다.

| 등급 | 예 | 넣는 것 | 넣지 않는 것 |
|---|---|---|---|
| 1 작은 타격 | 평타 1·2타, 총알 | 초승달(지금 그림), 적 흰 번쩍임 한 장, 작은 별(`flare-s`), 베기 자국, 별빛 몇 개 | 느려짐, 빛줄기, 화면 왜곡, 암전 |
| 2 강한 타격 | 3타, 내려찍기, 건틀릿 일격, 강화 일격 | 1 + 별 섬광(`flare`), 충격 고리, 바닥 충격, 큰 빛 번짐 | 화면 왜곡, 암전 |
| 3 관통 | 대시 공격 | 몸 잔상, 불꽃 궤적(`DashStreak`, 0.6초), 적마다 큰 초승달 + 별 섬광, 표식 | 암전 (표식이 다 차기 전에는) |
| 4 마무리 | 처형, 궁극기 마무리 | 예고 초승달 → 두 번의 일격(`FinisherCut`), 암전, 느려짐, 주인공 흰 실루엣, 화면 왜곡(`postfx.pulse`), 마지막에 블러 | 화면 정지 |
| 5 폭주 | 오버로드 | 기운이 모임(0.3초, 암전) → 입자 폭발, 화면 왜곡(모이며 부풀고 터지며 고리) | 화면 정지 |

게이지·강화 색은 모든 등급에서 따른다: `effects.zone_glow(player)`.

## 4. 큰 마무리의 시간표

처형과 궁극기 마무리는 `weapon.FinisherCut` 하나를 쓴다. 영상의 순서를 그대로 옮긴 것이다 (첫 일격 기준 초).

```
-0.14  예고 초승달: 회색 → 흰색 → 진한 색 → 가늘어짐      (배경 암전, 시간 x0.12)
 0.00  첫 일격: 흰 빛줄기 + 위아래로 긴 색 가시            (주인공 흰 실루엣, 적 검은 실루엣, 화면 왜곡 0.6)
 0.03  작은 진한 원반
 0.07  검은 띠 (빛줄기의 잔상)
 0.10  둘째 일격: 흰 빛줄기 + 큰 색 네 갈래 별             (피해는 여기서, 화면 왜곡 1.0)
 0.13  색 빛줄기 + 크고 진한 원반 + 가운데 작은 흰 별
 0.23  원반이 가운데부터 비워져 고리가 되고, 검은 선
 0.29  가는 흰 선과 고리 토막이 스러진다 → 0.31 가로로 번지는 블러
```

- 일격과 일격 사이에 **어두운 한 장**(검은 띠)이 있어야 두 번으로 읽힌다. 밝은 장면만 이어지면 한 덩어리의 번쩍임이 된다.
- 연출 객체는 **실제 시간**으로 돈다(`dt / effects.time_scale()`). 느려진 게임 시간으로 재생하면 연출도 같이 늘어진다.
  만든 프레임의 dt는 느려지기 전 값이라 건너뛴다(`fresh`).
- 연출 동안에는 직전 타격의 이펙트를 걷어 낸다(`FinisherCut.CLEAR`). 느려진 시간에 화면에 남아 주인공 장면을 덮기 때문이다.
- 캡처로 확인할 때도 실제 시간 기준으로 장면을 잡는다(`rt`가 넘을 때까지 한 프레임씩). 고정 프레임 수로 잡으면 다른 장면이 찍힌다.

## 5. 화면 후처리 (`src/postfx.py`)

사용자가 말하는 "블러·공간 왜곡"은 **배경까지 화면 전체가 휘고 색이 갈라지는 것**이다. 빛 띠를 겹치거나 화면을 조금 키워 겹치는 것은
그 뜻이 아니었다(두 번 반려). 세계 층을 그림판에 그린 뒤 32x18칸 그물로 다시 그리며 칸마다 가져올 자리를 옮긴다. UI는 휘지 않는다.

- `postfx.pulse(화면x, 화면y, strength, life)` — 한 번 터지는 굴절. 등급 4의 일격마다. 첫 일격 0.6, 둘째 1.0.
- `postfx.play(keys, 화면x, 화면y, ring=(t0, 속도, 두께))` — keys는 `(시각, 볼록 0~0.3, 색 번짐 px, 굴절 고리 px)`.
  모이는 연출은 볼록을 서서히 올리고(0.22), 터지는 순간 색 번짐 22px·고리 46px까지.
- 세기 기준: 색 번짐은 화면 높이의 1.5~2%(1080에서 16~22px)가 영상과 같다. 중심(주인공) 쪽은 덜, 가장자리는 크게 갈라지게 되어 있다.
  주인공이 무지개처럼 갈라지면 과한 것이다.
- 화면 좌표는 `camera.to_screen(세계x, 세계y)`. 설정의 '번쩍임 줄이기'면 꺼진다. SDL_RenderGeometry가 없으면 조용히 꺼진다.
- 등급 1~3에는 쓰지 않는다. 드물게 나와야 "큰 순간"으로 읽힌다.

## 6. 만드는 절차 (haze-fx의 절차에 더하는 것)

1. **등급을 정한다** (2절). 무엇을 넣지 않을지가 먼저다.
2. **참고가 있으면 잰다.** 영상은 `scripts/video_probe.js`로 프레임마다 밝기·흰색·색·앞 프레임과의 차이를 표로 뽑고, 값이 튀는 시각의
   프레임을 크게 본다. 눈으로만 보면 "두 번의 일격" 같은 구조를 놓친다(처음 분석에서 놓쳤다). 그림 한 장이면 색 면과 흰색의 넓이 비,
   배경의 변화(어두워짐·휨·색 갈라짐)를 먼저 본다.
3. **한 줄로 쓴다** → `tools/make_fx2.py`에 굽는다 → 모아 보기를 세 번 이상 고친다 (haze-fx 2절).
4. **지금 것 옆에 놓고 본다.** 이미 있는 이펙트를 바꿀 때는 예전 그림과 한 장에 나란히 놓는다. 모양과 빛이 더 낫지 않으면 바꾸지 않는다
   (초승달 17종을 통째로 바꿨다가 "찌그러지고 밋밋하다"로 되돌렸다). 시안은 `LOOK_ONLY`에 두고 사용자 확인 뒤에 굽는다.
5. **게임 화면에서 본다.** 배경·캐릭터 위에서, 실제 시간 기준 캡처로(playtest-capture). 동작 없이 서 있는 적(`_body_frame`이 `(None, 0)`)에게도
   해 본다: 처형이 그 경우에 게임을 종료시킨 적이 있다(`weapon.enemy_frame`으로 고침).
6. 규칙이 바뀌면 테스트를 먼저 고친다(AGENTS.md). 연출은 실제 시간으로 흐르므로 테스트에서는 `update(dt)`를 직접 불러 넘긴다.

## 7. 반려된 시도 (같은 실수를 하지 않으려고)

| 한 일 | 사용자의 말 | 배운 것 |
|---|---|---|
| 실행 중 사각형을 늘어놓아 고리·방사선·궤적을 그림 | "파이썬으로 찍어낸 블록 같다" | 시트로 굽는다 |
| 장면마다 납작한 원반·별을 한 장씩 찍음(도장) | "퀄리티가 떨어졌다, 스킬로 만들어야지" | 시간에 따라 흐르는 이펙트로 굽는다 (입자·빛) |
| 초승달 17종을 fxkit으로 통째로 다시 구움 | "찌그러지고 빛나는 효과가 사라져 밋밋하다" | 잘 되어 있던 것은 옆에 놓고 더 나을 때만 바꾼다 |
| 가는 선의 큰 고리로 오버로드 폭발 | "팡 터지는 느낌이 없다" | 첫 장에 꽉 찬 흰 덩어리, 이어서 꽉 찬 색 면 |
| 원반·가시·고리 도형으로 폭발 | "뾰족뾰족·동그라미 같은 도형 느낌" | 불규칙한 입자 무더기(FLAME·CHUNK)로 |
| 빛 띠를 겹친 것, 화면을 키워 겹친 것을 "블러"라고 함 | "배경이 다 왜곡되는 걸 말하는 거야" | 그물망 굴절 + 색 번짐 (postfx) |
| 시전 순간 화면 정지 + 컷인 띠 | "흐름에 방해된다" | 정지 대신 느려짐, 화면을 가리는 연출은 넣지 않는다 |

## 8. 아직 없는 것 (다음에 만들 후보)

- 평타 초승달을 진한 색 면 + 붓질로 (시안 `inari-smear`: 5방향·구간 색·가로 베기까지 하려면 예전 그림과 비교 통과가 먼저).
- 실행 중 궤적에 별빛 뿌리기, 대시 불꽃 궤적을 입자로, 주인공 몸 스미어.
- 타격 불꽃·헤이즈 폭발·궁극기 폭발·별 섬광·처형 원반을 도형에서 입자 구성으로 (haze-fx 5절의 목록).
- 적 공격 이펙트를 한 색 면으로 통일, 표식이 찼을 때 적의 붉은 테두리, 부드러운 연기.
- 타격음: 연출은 영상 수준에 가까워졌지만 소리는 그대로다 (사용자 검토 대기).
