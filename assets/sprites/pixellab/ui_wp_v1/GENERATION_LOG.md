# 무기·E 패널 그림 PixelLab 시험 기록 (2026-11-27, docs/opus/TASKS.md '4차' P1)

사용자: "여기에서 pixelLab을 이용해서 에셋을 뽑는건 어떤가?" (의견을 물은 것). 지휘 쪽이 "상한을 두고 시험해서 코드 그림과 나란히 보여 드리겠다"고 답했다.
그래서 시험이다: 기본 모습(`config.HUD_WEAPON_ART = 'code'`)은 바꾸지 않았고, `'px'`로 바꾸면 'row' 배치가 여기서 정리한 부품(`assets/ui/um_wpx_*`)을 쓴다.
정리·굽기: `python tools/make_ui_mist.py --wp` (`px_parts`). 상태·색 변형은 새로 뽑지 않고 코드로 만들었다.

- 도구: `create_image_pro_flash`만 썼다(64px 이하·96px 이하 모두 한 장에 5회). 화풍 기준 = 증강 갈래 아이콘 `assets/ui/up_mut_bloom.png`
  (1회차는 그대로 64x64, 2회차부터는 1배 도트로 줄인 `raw/style_bloom_1x.png` 32x32. 도트 2px 그림이라 [::2, ::2]로 그대로 줄어든다).
- 프롬프트에는 그림 설명만 적었다(게임 제목·저장소·사용자 정보 없음). 원문은 `docs/image_prompts.md`.
- 잔액: 시작 750.70 -> 끝 705.70 (45회). 상한 60회 안. 실패 2건(배경 지우기가 그림을 다 지움)은 과금되지 않았다.

## 2026-11-27 W6 확정 ('mix')
- 사용자: "결정을 둘러싼 테두리(소켓)은 기본(코드), 나머지 다른 소켓은 pixelLab". 기본 모습에 `crystal_s52`(결정)와 `slot_s64`(무기 칸 틀)를 쓴다. `socket_s61`은 'px' 값에서만.
- 새로 생성하지 않았다(잔액 705.70 그대로). 같은 원본을 다시 정리했다: 칸 틀은 깎인 모서리 둘레만 원본 색을 남기고 변을 다시 칠해 무기 색이 네 변에 고르게,
  들지 않은 칸은 모서리 8도트를 통째로 둔 9칸 줄이기. 결정 단계 색은 도트마다 밝기를 지키며(1.2배) 색만 바꿨다.
