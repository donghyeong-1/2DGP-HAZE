# 작업 세션(Opus) 지시문

설계는 기획 세션(Fable)이 쓰고, 구현은 작업 세션(Opus, "OPUS GAME 작업")이 한다. 2026-11-26 사용자 결정.
사용자가 작업 세션에 "docs/opus/TASKS.md의 O1을 진행해"처럼 말하면 그 작업을 한다.

## 공통 규칙
- `AGENTS.md`와 `docs/DECISIONS.md` 맨 위 "현재 기준 요약"을 따른다. 규칙을 바꾸는 일은 **테스트를 먼저** 쓰고 실패를 확인한 뒤 구현한다.
- 작업 하나 = 커밋 하나. 커밋 전에 `PYTHONUTF8=1 python tools/verify.py`. `docs/PROGRESS.md`는 예전 Codex 줄을 빼고 스테이지한다(인계 글의 명령).
- 화면이 바뀌는 일은 실제 창에서 찍어 확인하고(`playtest-capture` 스킬, 모니터 2, 설정·저장 파일은 임시 폴더로), 그림을 사용자에게 보낸다.
- 이펙트 그림은 `haze-fx` 스킬 절차로 굽는다(모아 보기를 세 번 이상 고친 뒤). 실행 중 사각형 덩어리로 그리지 않는다. 실행 중 확대는 **정수 배만**.
- 손대지 않는 것: 타격 이펙트(hit-*, haze-blast, 충격 방사선·고리, 별 섬광), 휘두르기 초승달, 대시 궤적(`weapon.DashStreak`)의 모양.
- 접근성: 번쩍이는 것은 `options.reduce_flash`를 따른다(흰 섬광 없음, 세기 절반).
- 여기 적힌 수치는 처음 값이다. 설계를 바꿔야 할 일이 생기면 멈추고 사용자에게 묻는다(사용자가 기획 세션과 상의한다).
- 끝나면 보고: 한 일, 통과한 테스트 수, 화면으로 확인한 것과 **확인하지 못한 것**.

## O2-1 보스 등장: 음악 정적 + 체력바 차오름

**목표**: 보스방에 들어서는 순간 음악이 뚝 끊기고, 이름 띠가 뜰 때 보스 곡이 시작된다. 등장씬이 끝나면 보스 체력바가 0에서 차오른다.

**지금 있는 것**
- `src/boss_intro.py`: `wait -> pan -> lines -> card -> out`. 위아래 검은 띠, 카메라 이동, 대사, 이름 띠가 이미 있다. `FULL`·`SHORT` 시간표, `hud_hidden()`.
- `src/play_mode.py`의 `music_for(stage)`: 살아 있는 보스가 있으면 바로 보스 곡을 고른다.
- `src/ui.py`의 `_draw_boss_bar`: 보스 체력바(등장씬 동안은 HUD가 숨는다).

**만들 것**
1. `boss_intro`에 "음악을 붙잡고 있는가"를 알려 주는 함수(예: `music_held()`): 등장씬의 `wait`·`pan`·`lines` 동안 True. `music_for`는 그동안 곡을 틀지 않는다(지금 곡은 멈춘다). `card`가 열리는 순간 보스 곡이 시작된다.
   - 다시 만난 보스(`SHORT`)도 정적이 **최소 0.5초**는 되게 한다.
   - 헤이즈 심장(아크가 쓰러진 뒤 내려온다)은 내려오는 동안이 정적, 다 내려와 등장씬이 시작되어 이름 띠가 뜰 때 곡.
   - `config.BOSS_INTRO`가 False면 예전처럼 바로 보스 곡.
2. 등장씬이 끝나(`out`) HUD가 돌아올 때 체력바가 0.6초에 걸쳐 0 -> 지금 체력까지 차오른다(빠르게 차고 끝에서 느려진다). 차는 동안 보스는 이미 움직여도 된다. 차오르는 동안 맞아서 체력이 줄면 목표 값이 줄 뿐이다.

**테스트 먼저** (`tests/test_boss_intro.py`에 추가하거나 새 파일)
- 등장씬 `wait`~`lines` 동안 `music_for`가 곡을 고르지 않고, `card`부터 보스 곡을 고른다. `SHORT`에서도 정적 0.5초 이상.
- 체력바 채움 비율이 등장씬 직후 0에서 시작해 0.6초 뒤 1이 된다. 등장씬이 없는 설정에서는 처음부터 1.

**화면 확인**: 크래셔 등장씬을 처음부터 끝까지 여러 장 찍어 체력바가 차오르는 중간 장면이 있는지. 음악은 화면으로 확인할 수 없으니 "소리는 사용자가 들어 봐야 한다"고 보고한다.

**하지 말 것**: 등장씬의 길이·대사·카메라는 바꾸지 않는다.

## O1 실루엣 컷인 (보스 페이즈 전환 + 궁극기 각성 증강)

**목표**: 화면을 한 가지 색으로 덮고 그 위에 **검은 실루엣**만 움직이는 짧은 연출(0.7초)을 만든다. 사용자가 준 참고(Moonwell Games의 궁극기·변신 영상: 붉은 원반과 검은 실루엣)를 새 그림 없이 지금 있는 재료로 만든다. 참고 영상의 그림은 가져오지 않는다.

**지금 있는 재료**
- `assets.silhouette(경로)`: 그림 모양만 흰색으로 채운 판. `sprites.draw_silhouette`, `assets.draw_clip_tinted`(색 곱하기), `assets.draw_clip(..., scale=정수)`.
- `src/impact_frame.py`: 검은 화면 + 흰 실루엣 + 붉은 선을 1~2프레임 보여 주는 장면(UI 층 바로 아래에 그린다). 구조를 참고한다.
- `effects.request_hit_stop`, `effects.request_slow_motion`, `postfx.pulse`(화면 일렁임), 구운 시트 `cut-mark-big`·`impact-rays-big`(색을 입히는 두 겹 시트).
- 보스 페이즈 전환: `boss.Boss._enter_phase2`(크래셔 '분노'), `ark.Ark._enter_phase`(2 '각성', 3 '폭주'), `gatekeeper.Gatekeeper._enter_phase2`, `heart.py`의 phase 2.
- 궁극기: `weapon.Ultimate`와 무기별 클래스(`ULT_NAMES`, `ULT_COLORS`, `ULT_DEEP`), 주인공의 시전 자세 그림 `hero6_ult`(옛 이름 `n09_ult`).

**만들 것**
1. 새 모듈 `src/cut_in.py` (규칙은 pico2d 없이 돌아가고 그리기만 화면을 쓴다):
   - `play(color, actors, word=None, duration=0.7)`: `actors`는 [(그림 세트, 번호, 보는 쪽, 화면에서의 자리, 정수 배율)]. 한 번에 하나만 돈다(도는 중이면 새 요청은 무시).
   - 시간표(0.7초): 0~0.08 들어옴(흰 섬광 한 프레임 뒤 단색. 번쩍임 줄이기면 섬광 없이) / 0.08~0.5 단색 바탕 + 큰 원반 + 실루엣이 40px쯤 미끄러짐(빠르게 시작해 느려진다) + 화면을 가로지르는 가는 선 2~3개 / 0.5~0.7 위아래에서 닫히며 빠짐.
   - 그동안 게임은 멈춘다(적도 플레이어도 움직이지 않고 피해도 없다). 끝나면 그대로 이어진다. 느려진 시간이 아니라 **실제 시간**으로 센다.
   - 큰 원반은 구운 그림 하나(`tools/make_fx2.py`, 색은 게임이 입힌다)를 정수 배로. 실루엣은 검정으로 물들여 정수 배(보통 3배, 헤이즈 심장처럼 큰 것은 1배).
   - `config.CUT_IN = True`(False면 아무것도 하지 않는다).
2. 보스 페이즈 전환에 건다: 위 네 곳에서 `cut_in`을 부른다. 색은 보스마다(크래셔 주홍, 문지기 청회색, 아크 청록, 심장 청록·페이즈 3은 진홍), 실루엣은 그 보스의 페이즈 자세 그림, 글자는 지금 띄우는 말('분노'·'각성'·'폭주')을 큰 글자로. 지금 있는 포효·흔들림·대사 한 줄은 컷인이 끝난 직후에 그대로 나온다. 같은 싸움에서 같은 페이즈는 한 번만.
3. 새 증강 **궁극기 각성** (`mutations.MUTATIONS`에 `ult_awaken`):
   - 강화 계열(`tide`)의 진화로 넣는다: `{'family': 'tide', 'tier': 'evo', 'ready': True, 'name': '궁극기 각성', 'desc': '궁극기 피해 +40%. 시전할 때 컷인이 나옵니다'}`. 강화 계열 기본 카드 둘을 가지면 열린다(다른 갈래의 진화와 같은 규칙). 공통 갈래라 어떤 무기를 들어도 나온다. 저주 증강 등급 2의 보상(진화 하나)으로도 나올 수 있다.
   - 효과: 궁극기 피해 x1.4(`config.ULT_AWAKEN_MULT`), 보스 피해 상한 15% -> 20%(`config.ULT_AWAKEN_BOSS_CAP`). 시전하는 순간 컷인: 색은 `ULT_DEEP[무기]`, 실루엣은 주인공 시전 자세 3배, 글자는 `ULT_NAMES[무기]`. 컷인이 끝난 뒤 궁극기가 나간다.
   - 이 증강이 없으면 궁극기는 지금과 똑같다(컷인 없음).
   - 카드 아래 안내 글(`mutations.card_info`)이 게이지 계열의 다른 카드와 어긋나지 않는지 본다(16자 안).

**테스트 먼저** (`tests/test_cut_in.py`)
- `cut_in.play`가 0.7초 뒤 끝나고, 도는 동안 두 번째 요청은 무시된다. `config.CUT_IN = False`면 아무 일도 없다.
- 컷인이 도는 동안 적이 움직이지 않고 플레이어가 피해를 받지 않는다.
- 크래셔·아크·문지기·심장이 페이즈를 바꿀 때 컷인이 한 번 요청되고, 같은 페이즈로 두 번 요청되지 않는다.
- `ult_awaken`: 강화 계열 기본 카드 둘이 있어야 카드에 나온다. 있으면 궁극기가 적 하나에게 주는 피해 합이 1.4배, 보스 상한이 20%. 없으면 그대로.
- 기존 테스트(증강 갈래 수, 카드 글 길이, 저주 보상)가 깨지지 않는다.

**화면 확인**: 크래셔 2페이즈, 아크 2·3페이즈, 심장 페이즈 전환, 증강을 가진 궁극기 네 무기. 컷인의 처음·가운데·끝 세 장씩. 번쩍임 줄이기를 켠 것도 한 번.

**하지 말 것**
- 2026-11-24에 뺀 궁극기의 화면 정지·이름 띠 컷인을 되살리지 않는다: 컷인은 0.8초를 넘기지 않고, 증강이 없으면 나오지 않는다.
- 새 캐릭터 그림을 만들지 않는다(지금 있는 자세 그림의 실루엣만).

## O3 빛줄기

**목표**: 방에 빛줄기를 더해 빛이 더 눈에 띄게 한다. 참고(Coggly Town의 픽셀 조명 5단계) 가운데 우리에게 없는 것만 넣는다.

**지금 있는 것 (바꾸지 않는다)**
- 환경광·가장자리 어둡게·안개: `src/atmosphere.py` (`draw_back`은 배경 바로 위, 캐릭터 아래에 그린다).
- 등 장식의 빛: `src/room.py`가 `DECOR_LAMP` 자리에 빛 그림을 그린다.
- 캐릭터 윤곽의 밝은 선(림라이트): `src/sprites.py`의 `RIM_COLOR`·`RIM_WIDTH`.
- 이펙트의 번지는 빛: `assets/light/glow_*.png` (빛 층은 반투명 예외).

**만들 것**
1. 빛줄기 그림 2~3종(`assets/light/shaft_*.png`, `tools/make_light.py`에 추가. 코드로 그린 부드러운 띠: 위가 좁고 아래로 퍼지며 옅어진다. 곧은 것 하나, 기운 것 하나).
2. 놓는 규칙(방 이름으로 정한 난수: 같은 방이면 늘 같은 자리):
   - 등 장식(`DECOR_LAMP`) 아래로 바닥까지 내려오는 옅은 빛 원뿔.
   - 방마다 0~2개의 기운 빛줄기를 천장에서(문·스폰 근처는 피한다, `room.near_marker`). 보스방은 0~1개.
   - 색은 구역 테마의 빛 색(슬럼 차가운 청백, 용광로 주황, 탑 청록). 은신처는 따뜻한 색.
3. 그리기: 더하기 섞기로 두 번. 배경 바로 위에 한 번(세게, 알파 0.18쯤), 캐릭터 위에 한 번(아주 옅게, 0.06쯤: 빛 속에 들어간 느낌). 천천히 숨 쉬듯 세기가 변한다(주기 4~6초).
4. 빛줄기 안에 떠다니는 먼지 알갱이 몇 개(2px, 느리게, `effects.draw_dot`).

**테스트 먼저**
- 같은 방 이름이면 빛줄기 자리가 늘 같다. 문·스폰 근처에는 놓이지 않는다. 방마다 개수가 규칙 안.
- 그림 파일이 있고 `tests/test_pixel_assets.py`가 통과한다(빛 층은 `assets/light/`).

**화면 확인**
- 세 구역과 은신처에서 같은 방의 전·후를 나란히.
- **적의 예고가 빛줄기 안에서도 읽히는지** 꼭 본다: 바닥의 붉은 예고 띠, 노란 낙하 표시, 감시 눈의 조준선, 적 머리 위 '!'. 묻히면 캐릭터 위에 그리는 두 번째 겹을 더 옅게 하거나 뺀다.

**하지 말 것**: 타일·배경 그림을 바꾸지 않는다. 화면 전체 밝기를 올리지 않는다. 물 반사는 넣지 않는다(발표 뒤로 미룸).

## O2-2 크래셔 착지 등장

**목표**: 크래셔를 처음 만날 때, 바닥에 그림자가 먼저 커지고 -> 위에서 떨어져 -> 착지하는 순간 슬로모션과 땅이 갈라지는 충격파가 난다. 크래셔만(문지기는 서서 지키고, 아크는 순간이동, 심장은 이미 내려온다).

**지금 있는 것**: `effects.ground_slam`, 구운 시트 `quake-blast`·`dust-land`, `effects.request_slow_motion`, `effects.add_trauma`. 등장씬은 `boss_intro`의 `FROZEN` 단계 동안 world를 갱신하지 않는다.

**만들 것**
1. 처음 만난 크래셔의 등장씬(`FULL`)에만 `pan` 뒤에 단계 하나(`drop`, 약 1.1초): 그림자가 0.6초 동안 커짐 -> 0.25초 낙하 -> 착지(슬로모션 0.35초, 흔들림 1.0, `ground_slam` 세기 1.6) -> 대사로 이어짐. 다시 만났을 때(`SHORT`)는 지금처럼 서 있다.
2. 그림자: 코드로 그린 납작한 어두운 타원 3~4크기(구운 그림, 정수 배 없이 크기별 그림).
3. **까다로운 점**: 등장씬 동안 world가 멈춰 있어서 이펙트도 멈춘다. 둘 중 하나로 푼다. (가) 등장씬 동안 이펙트 층만 갱신한다. (나) 낙하·착지를 world가 도는 짧은 구간에서 하고 그동안 플레이어를 무적·조작 불가로 둔다. 어느 쪽이든 그동안 플레이어가 맞지 않고, 보스가 공격을 시작하지 않아야 한다.
4. Enter·Space로 넘기면 바로 착지한 상태가 된다(지금의 넘기기 규칙과 같게).

**테스트 먼저**

## O5 강화 교체기 (v8 계획 3절)

**테스트 먼저** (`tests/test_combo.py` 또는 교체기 테스트가 있는 파일): 위 다섯 규칙 각각. 강화가 없을 때 교체기 피해가 예전과 같다.

## H1 HUD
사용자 결정(11/27): 나머지 화면을 확정된 두 컨셉에 맞추는 제안에 "제안대로 전부". HUD 몫은 한 줄 **"HUD는 철판을 걷고 가는 선 + 어두운 바탕."**
순서는 HUD -> 메뉴 화면 -> 고르는 화면, 묶음마다 사용자에게 그림을 보여 준 뒤 다음으로. 그림은 "코드 우선, 필요할 때만 PixelLab"(이번에는 생성 없음).
- 디자인 기준(지휘 쪽 해석): 증강 카드 A와 같은 말투. 판 = 가는 테두리 한 줄(화면 2px) + 거의 불투명한 어두운 바탕(카드와 같은 (9,12,21), 0.94).
  테두리 기본 회백 한 가지, 청록 = 헤이즈, 빨강 = 위험·저주, 금 = 합성·보상, 경고 노랑 안 씀. 판 안의 판은 한 겹으로, 조준점·적 체력·데미지 숫자에는 판 없음.
  막대는 평평한 색 + 가는 테두리(게이지 구간 색·눈금·바늘, 보스 페이즈 눈금·깎인 자국은 그대로). 고른 것 = 테두리가 밝아짐.
- 한 것: 부품 `um_hud_frame_<색>`(9칸 테두리 한 줄, 속 투명: line·dim·hot·red·cyan·gold·e1~e3), `um_fill_<색>_<높이>`(한 색 + 위 밝은 줄),
  `um_dash_on/off`·`um_combo_on/off/fin`·`um_dot_off`(철판 것과 같은 크기)를 `tools/make_ui_mist.py --hud`로 코드로 구웠다.
  `hud_kit`에 HUD 전용 `hud_panel`·`hud_fill`·`hud_bar`·`hud_icon`·`hud_tag`·`hud_keycap`을 더했다: mist면 새 부품, 다른 스킨이면 예전 함수를 그대로 부른다.
  예전 함수(panel·bar·tag·keycap 등)는 손대지 않아 일시정지·설정·상점·형태 선택·결과·크레딧·은신처 메뉴·대화는 이번에 변하지 않는다.
  HUD(`ui.GameUI`)·문 위 보상 판(`room._draw_reward`)·처음 안내 카드(`tutorial`)가 hud_*를 부른다.
  mist에서: 게이지·체력·보스 막대는 가는 테두리 판 하나(철판 몸통·양끝 쇠고리·하트 옆 결정·결정 끝장식 없음), 체력이 적어 깜빡일 때는 테두리가 빨강.
  무기 칸은 든 칸 = 밝은 테두리, 다른 칸 = 흐린 테두리(노란 꺾쇠 없음). E 칸은 준비·강화 중이면 테두리가 강화 단계 색(두꺼운 테 없음).
  칸 안 키 글자는 판 없이 글자만. 아이템 줄은 칸마다 판 대신 줄 전체에 판 하나. 재충전 막대는 노랑 대신 회색. 미니맵 지금 방은 노랑 대신 밝은 회백, 미니맵 바탕은 불투명(뒤 벽이 방 칸처럼 비쳐서).
  저주 표시는 빨간 테두리. 처음 안내 카드는 청록 띠를 빼고 제목을 밝은 회백으로. 자리·크기·글자 문구는 그대로(옮긴 것 없음).

  - **A 결정 소켓**: E = 마름모 소켓(카드 장식선의 마름모 말투)에 박힌 헤이즈 결정. 쓸 수 있음 = 청록 결정이 차 있다(카드 청록보다 한 단 어둡게), 못 씀 = 빈 소켓(결정 윤곽만, 색 없음),

### 부른 스킬과 그 기준에서 나온 주요 지적
- `design:design-critique`(첫인상·사용성·위계·일관성): 은신처에 전투 HUD가 그대로라 첫 화면의 위계가 흐리다, 기절 글자와 알림이 겹친다, 형태 카드 부제가 제목 아래 문장을 되풀이한다(1부에서 고침).
- `game-ui-ux`(앵커·배율·포커스·글자 크기 PC 18px·색만으로 알림 금지): 1280x720·1600x900은 1920 논리 화면을 정수 배가 아닌 비율로 줄여 도트가 고르지 않고 작은 글자가 약 15px로 줄어든다. 모든 메뉴는 열 때 고른 항목이 있다(통과). 화면 쌓기(game_framework 스택)로 위 화면만 입력을 받는다(통과).
- `design:accessibility-review`(명암비 4.5:1, 색만으로 알림, 깜빡임, 키보드): 어두운 바탕 (12,16,26) 위 명암비를 재서 ui.FAINT 4.2:1(보스 별칭·'강화 30%+'), mist_menu.PH_DIM_TEXT 4.3:1(설정의 안 고른 값), PH_DIM 3.3:1(감시 머리글 둘째 줄·버전)을 찾았다. 번쩍이는 것은 모두 '번쩍임 줄이기'를 따른다(title_storm·cut_in·impact_frame·effects, 통과). 미니맵 방 종류는 색 + 아이콘(통과).
- `design:design-system`(흩어진 값): 회백 글자 8가지((236,240,248)·(235,240,250)·(240,244,252)·(242,246,250) 등), 금 10가지, 청록 여러 값. 같은 뜻에 다른 색: 결과 화면의 '받은 헤이즈 결정'(금)과 '보유 헤이즈 결정'(청록), 짧은 알림·방 클리어에 금(금 = 합성·특별), 밸브 안내의 경고 노랑, 흐린 글자 FAINT가 ui·hud_kit에 다른 값. 아래 키 안내가 키 판(메뉴)과 글자만(카드형 화면) 두 모양.
- `design:ux-copy`(확인창은 행동과 결과를 말한다, 뻔한 안내 빼기): 판 포기 확인 '포기하려면 한 번 더 누르세요'는 어디로 가는지 말하지 않는다. '방 클리어 / 열린 문으로 이동하세요'가 매 방 뜬다.
- `input-systems`(동작 이름으로 읽기, 키 안내가 장치를 따른다): NPC 창·연습 메뉴·효과음 듣기·사망 결과가 `SDLK_f`를 직접 읽는다. 상호작용을 G로 바꾸면 G로 연 창이 G로 닫히지 않고, F(이제 강화)로 닫힌다. 키 안내는 게임패드를 써도 키보드 키 이름이다.
- `game-feel`(반응 없는 선택 금지, 짧게): 타이틀·일시정지·NPC 창·증강 카드는 이동·확인 소리가 있는데 설정·키 설정·연습 메뉴·사망 결과의 고르기는 소리가 없다. 메뉴 열고 닫기는 즉시(일시정지에서는 흔한 방식이라 두었다).

### 'AI 티' 점검 (3차 진단 다섯 가지 + 지시의 다섯 가지)
- 같은 틀 반복: mist의 가는 테두리 판이 안내 카드·진열대·획득 띠·보상 판·NPC 목록에 쓰인다. 한 벌로 정한 것(H1·S1)이라 두었다. 덜어낼 수 있는 장식은 뺐다: '방 클리어' 양옆 금 선.
- 과한 친절: '열린 문으로 이동하세요' 매번 -> 처음 하는 사람에게만. 설정 설명 열한 줄이 늘 떠 있다 -> 사용자 결정(아래). 연습 메뉴는 머리글·제목·부제에 '연습' 세 번 -> 부제를 뺐다. 은신처의 게이지·미니맵 -> 뺐다.
- 같은 뜻 다른 그림: 결정 색, 알림 색, 밸브 안내 -> 맞췄다. 키 안내 두 모양 -> 확정(S1)이라 둠.
- 글자: 상태 줄 '궁극기 준비!' 느낌표를 뺐다(순간 알림 '오버로드!'·'반격!'·'처형!'은 한 번 뜨고 사라지는 타격 글자라 두었다).

## U1-3 색 번짐 확인 (2026-11-27)
지휘 쪽이 U1 비교판(`U1_hideout_hud.png`, `U1_flow.png`의 '2 은신처'·'5 방 클리어')에서 화면 전체 색이 갈라진 것을 찾았다. 촬영 탓인지 게임 버그인지 가렸다.
- **무엇이었나**: `src/postfx.py`의 화면 연출(볼록 렌즈·색 번짐·굴절 고리, 보스 막타 줌)은 **실제 시간**으로 돈다. 오버로드는 1.05초(`effects.py` 오버로드 연출), 처형·궁극기 마무리는 0.5초, 보스 막타 줌은 0.6초 돌고 스스로 꺼진다.
  U1 촬영 도구는 프레임을 실제 시간보다 훨씬 빨리 돌려서, `hud_overload`·`hud_overload_toast`에서 켜진 오버로드 연출이 1초 안에 찍힌 다음 장면들(은신처, 방 클리어, 이벤트 방 등)에 그대로 남았다. 촬영 탓이 맞다.

### 수치로 확인한 것 (아무도 듣지 않았다)
- 117종 모두 44.1kHz 16비트 모노, 최대 -1.2dBFS 이하·잘림 없음, 앞 무음 0.5ms 이하, 변주 셋은 서로 다르다(스펙트럼 차이 평균 2.3~5.3). 실제 창(모니터 2)에서 두 묶음 모두 못 읽은 소리 0.
- 묶음별 재생 크기 중앙값 예전→새: 타격 -10.6→-10.3, 움직임 -11.7→-14.6, 적 -12.7→-11.1, 게이지 -8.4→-9.1, 보상 -9.0→-11.3, 메뉴 -15.7→-16.1, 보스 -7.0→-7.1, 환경 -23.0→-21.1. 같은 묶음 안 크기 퍼짐은 적 15.8→6.3dB, 게이지 11.0→7.1dB로 줄었다(타격은 일부러 색 소리를 작게 둬 11.4→12.8).
- 밝기: 휘두르기 5900→2300Hz(예전은 쉬익 하는 높은 잡음), 환경 5800→440Hz. 몸통(60~400Hz) 중앙값 타격 0.30→0.54.
- **타격음의 저음은 늘지 않았다**: 예전 무기 타격음은 합성한 낮은 사인이 거의 전부라 200Hz 아래 비율이 0.95~0.97이었다(impact_pipe 0.97→0.84, gauntlet 0.95→0.89). 새 것은 녹음의 타격 순간·중음이 들어가 비율은 조금 줄었다. 묵직함이 모자라게 들리면 낮은 사인 보조를 올린다.
- 총성 `shot`은 예전보다 5dB 크다(-16.2→-11.1). 자주 나는 소리라 크게 들리면 'shot' 목표를 내린다.
