# 픽셀 아트 일관성 규칙 (pixel_rules)

모든 AI 도구와 사람이 같이 따른다. 에셋과 그리기 코드를 추가·수정할 때마다 확인한다.

## 규칙과 현재 적용 상태
| # | 규칙 | 이 프로젝트에서의 적용 |
|---|---|---|
| 1 | 텍스처 필터는 최근접(Nearest). 밉맵·손실 압축(JPG 등) 금지 | `main.py`에서 `SDL_HINT_RENDER_SCALE_QUALITY = 0`을 설정. 스프라이트는 PNG(무손실)만 사용 |
| 2 | 기준 해상도 하나, 정수 배율로만 확대, 남는 공간은 검은 여백 | 창 1280×720, 배율 1배 고정. 창 크기를 바꾸는 기능은 만들지 않는다. 나중에 확대 기능을 넣으면 정수 배율 + 검은 여백으로만 한다 |
| 3 | 카메라와 모든 스프라이트 위치는 정수 픽셀 좌표 | 물리 좌표는 실수지만 **그릴 때** `assets.draw_image()`가 반올림한다. 카메라는 없음(한 방 = 한 화면) |
| 4 | 모든 요소에 같은 픽셀 크기. 스프라이트·타일·이펙트·UI 모두 1배 외의 배율로 확대·축소 금지 | `assets.draw_image()`는 원본 크기로만 그린다. 배율 상수는 없다. 단색 칸(UI 바)만 `draw_rect_image()`로 크기를 맞춰 채운다 |
| 5 | 실행 중 픽셀 아트를 회전하지 않는다. 미리 그린 회전 이미지나 90도 단위만 사용 | 코드에서 `rotate_draw`와 0이 아닌 각도의 `composite_draw`를 쓰지 않는다. 투사체(식칼 등)는 8방향(45도)을 미리 그린 프레임으로 만들거나 회전이 필요 없는 모양으로 한다 |
| 6 | 픽셀 폰트는 원래 크기로 사용 | **미해결**: 지금은 임시로 맑은 고딕을 쓴다(픽셀 폰트 아님). 라이선스가 허용되는 한글 픽셀 폰트를 정해 `docs/ASSETS.md`에 기록한 뒤 교체하고, 그 폰트의 원래 크기(배수가 아닌 값)로만 쓴다 |
| 7 | 파티클·이펙트도 스프라이트와 같은 픽셀 그리드 | 이펙트는 스프라이트 시트 프레임으로 만들고 같은 `draw_image()`로 그린다. 선·원 같은 벡터 도형은 디버그 표시에서만 쓴다 |
| 8 | 새 에셋을 넣기 전에 기존 타일 옆에 1배로 놓고 픽셀 크기가 맞는지 확인 | 아래 "에셋 추가 절차" 참고. 자동 검사는 `tests/test_pixel_assets.py` |

## 에셋 추가 절차
1. `docs/sprite_spec.md` 규격(80px 기준, 공통 팔레트, 외곽선 1px)으로 가공한다.
2. 반투명 픽셀이 없어야 한다 (알파는 0 또는 255만). 경계가 번지면 최근접 확대·반전에서 테두리가 지저분해진다.
3. 불투명 색은 64색 이하 (공통 팔레트).
4. 타일은 `config.TILE`(40px)의 배수 크기다.
5. 게임 안에서 기존 타일·캐릭터 옆에 1배로 놓고 눈으로 비교한다. 도트 굵기가 다르면 다시 가공한다.
6. `python tests/test_pixel_assets.py`를 통과해야 한다.

## 알려진 한계
- AI로 만든 이미지는 엄밀한 픽셀 격자를 따르지 않아 캐릭터마다 도트 굵기가 조금씩 다르다 (`docs/sprite_spec.md`의 한계 참고). 규칙 5번 비교 단계에서 가장 먼저 걸리는 부분이다.
- 배경 이미지(`placeholder/bg.png`)는 색 띠를 쓴 임시 그라데이션이다. 실제 배경은 같은 팔레트와 도트 크기로 만든다.
