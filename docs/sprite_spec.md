# 스프라이트 규격 (sprite_spec)

도트의 크기와 색감을 통일하기 위한 규칙이다. 새로 만들거나 다시 생성할 때도 이 규격을 따른다.

> **2026-11-07 갱신**: 아래 "규칙" 표의 키·팔레트 수치(80px, 약 60색 등)와 "만드는 방법"은 구 방식 기준이다. 현재 스프라이트는 hibit 방식으로 새로 만들어 `unified/`에 있고(구 파일은 `unified_legacy/`), 키는 문서 아래 "hibit 파이프라인" 표를 따른다. 구 방식 도구 `pixelize_sprites.py`는 `--legacy` 없이는 실행되지 않는다.

## 규칙
| 항목 | 규격 |
|---|---|
| 도트 밀도 | 모든 에셋이 같은 크기의 점을 쓴다. 게임 화면에는 전체를 1배로 그린다(기획서 5.3, `docs/pixel_rules.md`). 캐릭터마다 배율을 다르게 하지 않는다 |
| 키 (외곽선 제외) | 주인공 80px, 폐인 76, 투척병 80, 간수 88, 사냥개 52(길이 약 76), 아크 104, 크래셔 128 |
| 팔레트 | 전체 공통 약 60색 (외곽선 남색 #0B1020, 청록 계열 3색, 밝은 흰색 2색 포함) |
| 외곽선 | 어두운 남색 1px, 캐릭터 바깥쪽 |
| 방향 | 오른쪽을 본다. 왼쪽은 좌우 반전으로 처리 |
| 배경 | 투명 PNG |
| 파일명 | `{대상}_{동작}.png` (예: `n09_idle.png`) |

## 만드는 방법
1. 기준 이미지(주인공 `n09_idle`)의 도트 크기, 세부, 비율, 색감을 따르는 스타일 전이 방식으로 각 캐릭터를 생성한다. (프롬프트는 `docs/image_prompts.md`의 "주인공 원본 기준 세밀한 도트 시안")
2. 생성 원본은 `assets/sprites/detailed/`에 보관한다.
3. `python tools/pixelize_sprites.py` 로 통일 규격(키, 공통 팔레트, 외곽선)으로 가공해 `assets/sprites/unified/`에 저장한다. 줄일 때 BOX 필터를 쓰고 색 보정은 하지 않아 원본의 선명도를 최대한 유지한다.
4. 확인용 미리보기는 실행 시 `build/unified_preview.png`로 만들어진다. (git 제외)

## 현재 상태와 한계
- 대기(idle) 동작 한 장씩 7종만 있다. 걷기, 공격 등 동작 프레임은 없고, 구현 중에는 이동·기울임 같은 코드 연출로 대신한다.
- AI 이미지는 엄밀한 픽셀 격자를 따르지 않는다. 그래서 캐릭터마다 도트 굵기가 조금씩 다르다. (예: 간수는 다른 캐릭터보다 덩어리가 크다.) 줄이는 과정에서 줄어들지만 완전히 같지는 않다.
- 크기를 키우면(80px 기준) 세부는 늘지만 도트 느낌은 약해진다. 40px 기준은 너무 거칠어 폐기했다.
- PixelLab은 최대 64px라 이 규격(80px 이상)과 맞지 않는다. 필요하면 64px 기준으로 규격을 줄여야 한다.

## hibit 파이프라인 (2026-11-07 결정: 모든 캐릭터를 이 방식으로 다시 만든다)
기존 `pixelize_sprites.py` 방식(AI 도트 시안 → 줄이기)은 도트 굵기가 캐릭터마다 달랐다. 새 방식은 AI에게 도트를 그리게 하지 않고 **납작하고 선 없는 원화**를 받아 후처리로 픽셀을 만든다.
1. Codex에서 `$generate2dsprite`로 마스터 스틸컷을 만든다 (`--finish hibit`, 옆모습·오른쪽, 마젠타 배경, 1024×1024). 결과 중 `master_rgba.png`(배경 제거본)를 쓴다.
2. `python tools/finish_character.py <master_rgba.png> <이름>`: 팔레트 24색, 가장자리 커버리지 0.3, 외곽선 #0b1020 1px, 키는 아래 표.
3. 결과는 `assets/sprites/forge/<이름>_idle.png`. 확인 후 `unified/`를 대체한다. 대체 전에 `python tests/test_pixel_assets.py`와 게임 안 1배 비교를 거친다.

| 이름 | 키(외곽선 포함) | 1280×720 기준 (구) |
|---|---|---|
| n09 (주인공) | **123** | 82 |
| enemy_slum / enemy_thrower / enemy_guard | **117 / 123 / 135** | 78 / 82 / 90 |
| enemy_hound | **81** | 54 |
| boss_ark / boss_crasher | **159 / 195** | 106 / 130 |

2026-11-11 결정: 화면 1920×1080, 타일 60px로 올리면서 모든 키를 1.5배로 한다(`tools/finish_character.py`의 `SCALE`). 팔레트는 40색으로 늘렸다(`check_sprites.py` 상한은 48색). 7종을 이 크기로 다시 만드는 작업은 `docs/codex/`의 T01~T03.

**알려진 한계 (주인공 시험 결과)**: 눈 같은 작은 얼굴 요소는 8배 축소에서 사라진다(눈이 1px도 안 됨). 마무리 설정으로는 약하게만 살아나므로, 원화에서 **눈을 굵고 크게, 머리를 크게(키의 약 1/6)** 그려 달라고 요청한다. 주인공 시험은 몸 너비가 16~20px로 기존(30px)보다 가늘다. 어깨를 넓게 요청한다.
